THE RULE AS BUILT (frozen from the spec, nothing tuned)
  calm      Binance 1 s trailing-5-min vol before the open < 0.304, via poly_fav.FavBrain - the SAME
            frozen call the 8787 engine makes. Not re-derived here.
  window    sec 60-180; 180 s is also the hard cancel
  favourite the side whose best BID is in [0.60, 0.80]
  post      BUY 5 shares at that best bid, post_only=True (the SDK supports it: create_limit_order
            (..., post_only=True)), so the GTC-below-the-ask fallback in the spec is not needed
  cancel    immediately on a Binance spot move >= 2 bps against our side over the last 1 s; at 180 s;
            at the candle end; on the favourite flipping; on the book leaving the band; on vol leaving
            calm. A risen bid is a cancel with reason 'bid_moved' and a fresh post next pass.
  limits    one open order at a time, at most one FILL per candle
  settle    held to settlement, graded on the VENUE's own resolution (gamma mirror), never a Binance
            close. Maker BUY pays price, no taker fee: pnl = shares*(1-price) on a win, -shares*price on
            a loss.
  stops     -$10 realised in a UTC day -> off for the day; -$20 realised lifetime -> off for good.
            Checked before EVERY post, not once at startup.

A BUG THE BUILD FOUND, AND HOW
  I cross-checked my book parse against the 8787 engine's OWN parse of the same venue feed, second by
  second. On every overlapping second my best ask was None - I had no book at all. Cause: the gamma
  mirror usually does not yet carry the NEXT candle's tokens when the probe subscribes, so the
  subscription held only the current pair, while the resubscribe bound (copied from the engine) was
  ep+345. That left the probe holding STALE tokens for the first ~45 s of every candle. It is outside
  the 60-180 s window, so it would never have fired a wrong order - but it is silent blindness, and it
  becomes a live bug the moment the window widens. Fixed: when the next pair is unknown the
  subscription now ends at the roll instead of ep+345. Blind seconds measured 0/175 after the fix,
  against 43/43 before.
  Residual: my best ask and the engine's agree on 111/175 seconds, the rest within about a tick. Two
  independent websocket clients sampled at different moments inside the same second will differ on a
  fast book; the probe prices off its OWN book at its OWN moment, which is what the order it is about
  to send requires. This is a parser sanity check, not a fill test - it is deliberately NOT used to
  estimate anything about fills.

  one_pass takes an injectable clock for exactly this reason - otherwise those tests would SKIP
  whenever the wall clock sat outside 60-180 s, and a skipped test proves nothing.

TWO THINGS I GOT WRONG AND THE TESTING CAUGHT - both were mine, not V's brief
 A. I added an ask-side crossing test for RESTING orders on my own initiative. It is backwards. A
    resting BUY at 0.70 meeting an offer at 0.70 is US BEING FILLED AS THE MAKER - the exact event
    this probe exists to measure. We cross nothing; the venue matches them. On a one-tick-spread
    book it fires constantly: the 18:30 dry run pulled all 3 orders, each inside a second, giving
    the same "never fills" symptom as the 17:00 churn from the opposite cause. The crossing test
    now lives ONLY in the post branch, where it belongs.
 B. The dry run was not simulating what it claimed. First it cleared self.resting immediately, so
    nothing ever rested and the run measured only the per-candle cap - caught because the first
    post-fix run reported exactly 3 posts on all 3 calm candles. Then, once a virtual order rested,
    that order was not in the book being read, so the real bid ticking down one fired V's rule 3 on
    an order that live would still be at the front of the queue: 6 of 9 cancels on the 18:35-19:00
    run were that artifact, and it made resting life look like 1.5 s. Dry mode now puts our own
    virtual order into the book on its side, exactly as the venue would. Same candle, same rule:
    2% time-in-book before the correction, 45% after. Do not read any pre-19:07 dry-run life figure.
 C. The unit tests were appending real log rows to THIS committed file, because log() defaulted to
    it. 32 such lines removed; the log path is now per-instance and the tests write to a temp file.
