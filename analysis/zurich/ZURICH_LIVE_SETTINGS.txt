WHAT `sl` ACTUALLY MEANS IN THE CODE - and it is NOT what "in trade" implies
  poly_dashboard.py daily():   p = sum(results.pnl) over the engine's day window
                               halted = (tp>0 and p>=tp) or (sl>0 and p<=-sl)
  poly_dashboard.py allowed(): returns False when daily()['halted'] -> btc_model calls
                               self.ui.allowed(kind) before every order, so a halt BLOCKS the lane.
  So it IS enforced, and three properties matter:
  1. IT IS A DAILY CUMULATIVE LOSS LIMIT, NOT A PER-TRADE EXIT. Nothing closes or exits an open
     position at -$40. It stops NEW orders once the day's summed realised PnL reaches -$40. A single
     $5 trade can never trigger it; it takes about eight full losses in one window.
  2. THE WINDOW STARTS AT 12:00 LONDON, NOT MIDNIGHT (day(): hour=12, minus a day if now is earlier).
     The window in force right now is 09-29 12:00 BST -> 09-30 12:00 BST.
  3. IT HALTS EVERY LANE, not only EF - allowed() applies it to MAIN and REVERSAL too. With those two
     already off it currently only bites EF.
  It counts the `pnl` column, which is REAL money only: in this window 95 result rows sum to
  pnl +0.00 while shadow_pnl is -2.81, i.e. the paper/shadow trades from before master was armed do
  NOT count toward the stop. Headroom right now is the full -40.00.
