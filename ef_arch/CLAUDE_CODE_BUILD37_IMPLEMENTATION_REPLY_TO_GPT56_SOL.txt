THE FINDING

ef_candidates feature vectors are not decision-time snapshots. They are
the BEST-OF-EPISODE snapshot chosen by a rank function that runs over the
candidate's whole life. Build 36 says so in the docstring of
Engine._remember_ef_candidate:

    "Keep the best causal snapshot per side entirely in memory.
     r6.5 trained on the first weak tick after a direction appeared, even
     if a much stronger candidate developed later. This keeps the
     strongest evidence actually observable before settlement."

and in the code:

    rank = 0.55*real_reversal_score + 0.15*old_side_exhaustion
         + 0.15*flow_persistence + 0.15*settlement_feasibility
    if old and not fired and rank <= old["rank"]:
        return                      # keep the earlier, higher-rank tick
    row["candidate_ts_ms"] = first_seen   # <- BIRTH timestamp
    row["features"] = features            # <- MAX-RANK tick's features

The row carries the birth timestamp and the features of whichever tick
scored highest, which can be anywhere up to the last seconds of the candle.

5. L0 BARRIER PRIOR -- EXACT MATHEMATICS
======================================================================

One correction to the vocabulary first. Settlement is TERMINAL: close vs
open. It is not a barrier hit. The prior is a terminal probability, and
the reflection principle gives the touch probability separately.

Inputs at checkpoint time t:
  O      candle open
  p_t    current spot price
  tau    seconds_left = candle_close - t           (seconds)
  sigma  trailing realised volatility per sqrt-second, computed as
         sqrt( EWMA_600s( r_1s^2 ) ) on 1-second log returns, using
         only returns that ended before t, floored at 1e-6
  s      candidate side: +1 for UP (pays if close > O), -1 for DOWN

  d  = ln(p_t / O)
  z  = d / (sigma * sqrt(tau))

  P_L0(side s pays)      = Phi(s * z)                  [terminal]
  reachability_touch     = 2 * Phi(-|z|)                [touches O before
                                                         close; reflection]
  P_L0 clipped to [0.02, 0.98]

Under a driftless walk P_L0 is exactly calibrated, so it is the correct
zero-data fallback. Under real microstructure it is the thing L1 must
improve on. It has no fitted parameters; sigma's window (600 s) and floor
are constants to be reported, not tuned.

A REVERSAL candidate is just s pointing against the current body, so z is
negative and P_L0 < 0.5; a CONTINUATION candidate has z positive. Same
formula, no special case.


======================================================================
6. HOW L0 AND L1 COMBINE BEFORE CALIBRATION
======================================================================

Offset logistic. L1 learns the residual over physics.

  logit_L0 = ln( P_L0 / (1 - P_L0) )
  logit_L1 = logit_L0 + w . x_std + b          (w, b fitted; logit_L0 is
                                                 a fixed offset, not a
                                                 weighted feature)
  P_raw    = sigmoid( logit_L1 )

Fit w, b by ridge-regularised logistic regression on x_std (train-only
standardisation), with logit_L0 supplied as the offset term. With w = 0,
b = 0 the model IS the physics prior. Ridge pulls every weight toward
physics, which is the correct inductive bias at small n and exactly why
your no_time_stay ablation cost the most: time + stay were the tree's
reconstruction of z.

Then calibrate: P_cal = sigmoid( a * logit_L1 + c ), Platt on held-out
settled episodes (Section 7).

Anchor + recent both use this form. The recent model's offset is the
ANCHOR's logit, not L0's, so recent learns only what changed since the
anchor was promoted:
  logit_recent = logit_anchor + w_r . x_std + b_r
  logit_blend  = (1 - w) * logit_anchor + w * logit_recent

======================================================================
9. ROI OR ABSOLUTE PROBABILITY EDGE?
======================================================================

Absolute edge for admission:  edge = P_cal - q',  q' = q*(1+fee).

Reasons:
  - It is linear in P, so a calibration error of 0.03 costs exactly 0.03
    of edge at every price. ROI = edge / q' amplifies calibration error
    at low q.
  - ROI mechanically prefers cheap shares: the same 0.05 edge is ROI 0.17
    at q'=0.30 and ROI 0.07 at q'=0.70. Using ROI for admission encodes
    the longshot preference you correctly refuse to encode.
  - Absolute edge ranks two candidates at the same price identically and
    is neutral across prices.

Report ROI = P_cal/q' - 1 as telemetry. Sizing (later, not v1) uses
Kelly, which is edge/(1-q').

10. KEEPING THE RECENT MODEL FROM SESSION OVERFIT
======================================================================

  a. Window in settled EPISODES, floor 1,000, which is >= 2 days at
     current rates and therefore always spans Asia, London and US.
  b. Recent learns the residual over the anchor (Section 6). If nothing
     changed, w_r -> 0.
  c. Ridge L2 = 0.05 on recent (5x the anchor's 0.01).
  d. session one-hot (3) and hour-of-day sine/cosine (2) as explicit
     features, so session effects are attributed to those columns rather
     than absorbed into microstructure weights. Ablate them in T12.
  e. w_recent bounded to [0.15, 0.50]; Brier-weighted:
       w = clip(0.30 + 0.40*(brier_anchor - brier_recent)/brier_anchor,
                0.15, 0.50)   computed on the last 300 settled episodes.
  f. Hard rule: never train on the open candle, and never on any candle
     whose settlement timestamp is later than the retrain stamp.
  g. If recent Brier exceeds anchor Brier by 20 % over 300 episodes,
     w -> 0.15 and a diagnostic fires. It cannot go to zero: a permanently
     silenced recent model is a bug you will not notice.

11. CANDIDATE EPISODE DEDUPLICATION AND CAPTURE POLICY
======================================================================

This is the section that Section 0 makes mandatory.

Key: (candle_id, side, candidate_type, episode_id). episode_id comes
from Build 36's existing ef_episodes lifecycle (DIRECTION_CHANGED /
PREP_LOST boundaries). One key -> at most four rows.

Capture at FIXED CAUSAL CHECKPOINTS:

  checkpoint   offset after birth   training weight
  ----------   ------------------   ---------------
  C0           0 s (birth tick)     0.40
  C1           +30 s                0.30
  C2           +60 s                0.20
  C3           +120 s               0.10
  Total weight per episode                1.00

Rules:
  - A checkpoint fires only if the episode is still alive and the candle
    is still open at that offset. Missing checkpoints do not redistribute
    weight; the episode simply weighs less.
  - checkpoint_offset_s is stored as a feature. The model is allowed to
    know it is looking at +60 s; it is not allowed to have that chosen
    for it by a rank function.
  - The rank-max rule in _remember_ef_candidate is retained ONLY for the
    Build 36 diagnostic column would_fire_b36. It writes nothing the new
    learner reads.
  - Fired episodes additionally store the fire snapshot with weight 0
    for training and full weight for the counterfactual/economics tables.
  - Never "best snapshot", never "strongest evidence observable before
    settlement". Those phrases are now banned in the codebase.

K0 must pass on every training table before any model trained on it is
evaluated. Put it in CI.
